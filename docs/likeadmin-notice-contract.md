# M01 通知业务契约

> 参考：LikeAdmin 1.9.4 通知业务  
> Peanut：当前工作区实现  
> 状态：已验收  
> 边界：本文只覆盖通知渠道、验证码场景模板、发送/验证和发送记录；不重复 C01、C02

## 1. 复刻口径

M01 复刻的是通知业务需求、能力、实体关系、规则、权限语义、状态流和用户可见结果。Peanut 保持自己的 ThinkPHP 分层、命名、路由、接口协议、前端框架和数据表设计。

以下内容不属于一致性门槛：

- UI 布局、页面路由和控件形式；
- 接口路径、参数名、响应 envelope 和精确错误文案；
- LikeAdmin 的场景数字 ID、短标签、类名和表名；
- 第三方 SDK 或 HTTP 签名代码的具体组织方式。

不得为形式相似增加双路由、双字段、参数别名或其他兼容层。验收只比较管理员和用户能够完成的业务，以及相同条件下的数据与状态结果。

## 2. 业务知识图谱

```text
管理员角色 ---- 授权 ---- 渠道配置 / 场景模板设置 / 发送记录查看
                              |              |
                              v              v
                         短信渠道       固定通知场景
                         | 阿里云       | 登录验证码
                         | 腾讯云       | 绑定手机号
                         ` 默认渠道     | 变更手机号
                                        ` 找回密码
                                              |
用户业务动作 ---- 触发发送 ---- 场景 + 手机号 + 模板变量
                                              |
                                              v
                                 生成验证码并渲染内容
                                              |
                                              v
                                    默认短信渠道发送
                                       |           |
                                     成功          失败
                                       |           |
                                       `---- 发送记录 ----'
                                              |
                                      后续业务校验验证码
                                              |
                                   未验证 ---> 已验证
```

核心关系：

| 实体 | 业务信息 | 关系与约束 |
|---|---|---|
| 短信渠道 | 服务商、签名、访问凭据、启停、默认渠道 | 支持阿里云和腾讯云；发送时只使用一个有效默认渠道 |
| 通知场景 | 稳定业务标识、名称、说明、接收者、可用变量 | 预置四个验证码场景，不由管理员任意新增或删除 |
| 场景模板 | 服务商模板 ID、内容模板、启停状态 | 从属于一个场景；验证码模板使用 `code` 变量 |
| 发送记录 | 场景、渠道、服务商、接收手机号、内容快照、发送状态、错误和时间 | 每次实际进入服务商发送的尝试形成可追踪结果 |
| 验证状态 | 验证码、是否已验证、校验次数、验证时间 | 从属于验证码发送记录；成功后不能再次使用 |
| 用户/会员 | 手机号和触发的登录、绑定、变更、找回密码动作 | 发送及校验必须按场景和手机号隔离 |

## 3. LikeAdmin 1.9.4 业务能力

### 3.1 短信渠道

LikeAdmin 提供阿里云和腾讯云两种短信服务商配置：

- 管理员可以查看两种渠道的启停状态并分别设置凭据、短信签名和状态；
- 阿里云需要应用访问凭据和签名，腾讯云需要应用 ID、访问凭据和签名；
- 启用一个渠道时，该渠道成为默认发送渠道，原默认渠道被停用；
- 发送前必须存在默认渠道，且该渠道已启用并具备可用配置；
- 渠道未配置、已关闭或驱动不可用时，发送失败且不能伪装成成功。

LikeAdmin 在关闭当前渠道时可能保留一个指向已关闭渠道的默认值。Peanut 不复制该不一致状态：关闭当前默认渠道后应清除或重新选择有效默认渠道。

### 3.2 固定验证码场景模板

LikeAdmin 安装数据提供四个用户验证码场景：

| 业务场景 | 用途 | 模板变量 |
|---|---|---|
| 登录验证码 | 手机号验证码登录 | `code` |
| 绑定手机验证码 | 用户首次绑定手机号 | `code` |
| 变更手机验证码 | 用户更换已绑定手机号 | `code` |
| 找回登录密码验证码 | 用户通过手机号重置密码 | `code` |

管理员能够查看场景名称、业务说明、通知类型和短信启停状态，并设置短信服务商模板 ID、内容模板和启停状态。

参考数据结构预留系统通知、公众号模板消息和小程序提醒，但 1.9.4 的四个已安装场景只声明短信支持，管理页面也只呈现短信设置。因此 M01 的复刻核心是短信场景，不把未形成可用业务闭环的预留字段当作必须能力。

### 3.3 发送与验证状态流

```text
发送请求
  -> 校验手机号和业务场景
  -> 读取已启用场景模板
  -> 检查同一手机号发送频率
  -> 生成 4 位验证码
  -> 替换模板变量
  -> 调用默认短信渠道
  -> 记录成功或失败及服务商结果

未验证验证码
  -> 5 分钟内、场景和手机号匹配、验证码正确：标记已验证
  -> 验证码错误：增加校验次数，仍保持未验证
  -> 超过 5 分钟：失效
  -> 已验证：不能再次使用
```

发送规则：

- 同一手机号在任意验证码场景下，最近 60 秒已有成功发送时拒绝再次发送；
- 场景必须存在并启用，模板 ID 与内容必须可用；
- 发送成功与失败均以服务商调用结果为准；
- 频率限制只由成功发送记录触发，失败发送不占用一分钟成功额度；
- 验证时必须隔离场景和手机号，不能使用另一场景的验证码完成当前业务。

### 3.4 发送记录

LikeAdmin 的发送链路保存短信记录，并另存一条通用通知记录。短信记录包含场景、手机号、渲染后内容、验证码、发送状态、发送时间、服务商结果、验证状态和校验次数。

LikeAdmin 1.9.4 没有独立的后台发送记录页面，但“发送结果可持久追踪”属于业务能力。Peanut 可以使用一张发送记录表同时承载通知快照、服务商结果和验证码验证状态，不需要复制两张语义重叠的表。

## 4. Peanut 映射

| LikeAdmin 业务概念 | Peanut 当前实现 | 映射结论 |
|---|---|---|
| 短信服务商配置及默认渠道 | 配置服务中的阿里云、腾讯云和默认服务商 | 同一能力；Peanut 保存时脱敏密钥并保证默认渠道有效 |
| 固定通知场景 | `NoticeScene` | 四个场景按稳定字符串 code 唯一，不复制参考数字 ID 和短标签 |
| 场景短信模板 | 场景上的模板 ID、内容和启停状态 | 与场景一体管理，符合参考业务关系 |
| 短信记录 + 通知记录 | `NoticeLog` | 合并为单一发送事实，保留发送及验证所需信息 |
| 场景发送与验证码校验 | `VerificationCodeService` 及短信驱动 | 负责频控、生成、发送、落日志、过期和单次核验 |
| 管理员通知权限 | Peanut 菜单和按钮权限 | 按渠道查看/保存、场景查看/设置、日志查看/详情独立授权 |

Peanut 当前还存在通用通知模板、邮件渠道和通用 `NoticeService`。这些是 Peanut 扩展能力，不是 LikeAdmin 四个验证码场景的必要依赖，也不作为 M01 业务等价的验收门槛。不得为迁就扩展能力再建立第二套验证码场景或重复发送链路。

## 5. Peanut 管理端能力要求

### 5.1 渠道配置

- 展示阿里云、腾讯云的配置状态和当前默认服务商；
- 分服务商保存必要凭据、签名、地区等配置；
- 密钥读取时只显示已配置状态，未修改的掩码值不能覆盖原密钥；
- 启用服务商前校验配置完整；
- 同一时间至多一个短信服务商处于启用并作为默认渠道；
- 禁用默认服务商后不得残留可被发送链路误用的默认配置。

邮件配置属于 Peanut 扩展，不能影响短信渠道的状态和发送结果。

### 5.2 场景模板

- 展示四个固定场景的名称、说明、接收对象、短信状态和内容；
- 管理员只能设置模板 ID、内容和启停状态，不能改变场景标识或删除业务场景；
- 启用时模板 ID、内容必填，验证码内容必须包含 `code` 变量；
- 关闭场景后用户发送请求被拒绝，且不产生成功发送记录；
- 保存失败不得部分更新模板或状态。

### 5.3 发送记录

- 发送记录只读，管理员不能从管理端篡改发送或验证状态；
- 支持按接收者、场景、渠道、发送状态和时间查询；
- 列表按新记录优先，详情能看到内容快照、服务商、发送结果、失败原因和验证摘要；
- 验证码明文属于敏感信息。验收已确认后台页面和普通列表不直接暴露验证码；
- LikeAdmin 1.9.4 保存短信及通知记录，但没有独立的后台日志页面。Peanut 的只读日志页面是非阻塞运维扩展，不要求 LikeAdmin 具有相同页面或路由。

## 6. 权限语义

普通管理员的通知能力按以下动作独立授权：

- 查看渠道配置、保存渠道配置；
- 查看场景列表/详情、保存场景模板；
- 查看发送记录列表和详情。

拥有能力时可以看到入口并完成对应动作；撤销后入口不可用且服务端拒绝直接调用；其他已授权能力不受影响。权限拒绝不得改变渠道配置、场景模板、发送记录或验证码状态。Peanut 使用自己的权限标识和页面结构，不要求复刻 LikeAdmin 菜单 ID。

## 7. 状态流与不变量

### 7.1 渠道与发送

```text
未配置/已关闭渠道 --补齐并启用--> 默认可用渠道
默认可用渠道 --切换服务商--> 新渠道启用且成为默认，旧渠道停用

发送尝试 --服务商受理成功--> 成功记录
发送尝试 --服务商拒绝/网络异常--> 失败记录 + 失败原因
```

### 7.2 验证码

```text
未验证 --正确且未过期--> 已验证
未验证 --错误--> 未验证 + 校验次数增加
未验证 --超时--> 失效
已验证 --再次校验--> 拒绝
```

业务不变量：

1. 固定场景 code 唯一，设置模板不改变场景身份。
2. 启用的默认短信渠道至多一个，默认值不能指向已关闭渠道。
3. 发送前置条件失败不能产生成功记录。
4. 每次实际调用服务商的发送尝试最多形成一条发送事实，不产生重复日志。
5. 成功记录保存当时的场景、接收者、内容和服务商结果，不因后续模板修改而变化。
6. 同一手机号 60 秒成功发送频控跨四个验证码场景生效。
7. 验证码只在对应场景、手机号、最近成功且未验证的记录上生效，有效期 5 分钟。
8. 错误校验增加次数但不提前标记已验证；成功校验只允许一次。
9. 权限拒绝、无效输入和查询操作不改变渠道、模板、日志或验证状态。
10. 密钥不能通过配置详情、发送记录或普通错误信息明文泄漏。

## 8. 外部服务验收边界

本轮已在隔离配置和可控数据库夹具边界内完成配置选择、模板字段保存回读、频率限制、日志、不变量和验证码核验。该结论证明本地业务逻辑，不等同于第三方平台已受理或手机已收到短信。

真实短信到达手机尚未验证。真实送达依赖有效的阿里云或腾讯云账号、已审核签名、已审核服务商模板、可用额度、网络和真实接收号码。没有这些外部条件时，只能验证“请求被服务商受理或拒绝”及本地记录，不能宣称用户手机已收到短信。真实送达应作为有凭据环境下的一次独立外部验收，不得在文档中以模拟成功替代。

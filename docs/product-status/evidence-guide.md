# 能力证据规则

能力状态引用证据，不复制原始日志。证据按以下优先级使用：

1. 不可变 Tag、GitHub Release 或 Registry 版本；
2. 完整 Git commit/tree 上已完成的专属 CI Gate；
3. 使用已登记资源、精确候选和唯一租约的运行时验收报告；
4. 仓库内不可变 JSON 摘要、浏览器报告或数据库 Gate 摘要；
5. 已合入的架构/验收合同，仅用于证明边界，不单独证明 Runtime 已通过。

聊天转述、任务标题、开放 PR、移动分支 HEAD、未提交 worktree 和“已经通知”都不是完成
证据。

## 证据最小字段

运行时或发布资格证据应能确定：

- 完整候选 commit，必要时包括 tree；
- Gate 名称和完成结论；
- 实际使用的登记资源 ID、环境和地址；
- CI run、报告路径或不可变 Release 引用；
- 验证日期与必要的新鲜度；
- cleanup、恢复和租约释放结果。

账本只保存稳定 `ref`。凭据、Cookie、临时日志、动态租约内容和个人目录中的敏感输出不得
写入账本。

## 失效和刷新

- 修改能力直接实现、公共合同、Schema、资源身份或验收脚本时，原 `verified` 证据必须复核。
- 纯文档、注释或与该能力无关的 app-owned 变化，不自动使证据失效。
- 发布快照一旦冻结不得回写；后续变化记录在当前 ledger 和新的发布快照中。
- 外部链接失效时应补充新的稳定引用，但不得重写原始测试结论。

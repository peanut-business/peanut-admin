# 暂缓与范围外管理

`deferred` 和 `out_of_scope` 不是普通待办：

- `deferred` 表示能力属于可能的产品方向，但当前经过决定暂不执行；
- `out_of_scope` 表示能力不属于本产品、当前阶段或当前安全边界。

两者都必须在 `capability-ledger.json` 中记录 `reason` 和 `resume_when`。本文件不重复列出
具体能力，避免形成第二份事实源；当前清单由 `README.md` 自动展示。

恢复暂缓项时，应先把状态改成 `planned`，补齐目标 release、验收条件、直接依赖和资源
登记，再开始实现。范围外能力只有在产品边界或独立项目授权正式变化后才能恢复。

以下情况不得通过状态调整绕过：

- 把 app-owned 文件改成 managed 以便升级器静默覆盖；
- 为了通过升级而自动重构用户业务源码；
- 将未登记的数据库、服务、端口、mock 或容器作为 fallback；
- 把独立运营平台塞入核心包或 SaaS Host；
- 用“未来会处理”替代具体恢复条件。

# S01 系统设置、充值支付与微信登录业务契约

## 目标

Peanut 对齐 LikeAdmin 1.9.4 的系统设置业务能力，不要求页面、路由、接口路径、参数命名或响应外壳相同。Peanut 只保留一套 canonical 数据和实现，不提供参考系统兼容层。

## 产品能力图

| 能力 | LikeAdmin 1.9.4 | Peanut canonical 实现 | 用户结果 |
| --- | --- | --- | --- |
| 用户与登录设置 | 默认头像、账号/短信登录、协议、强制手机、第三方微信 | `default_image`、`login` 配置 | 保存后所有客户端立即消费同一配置 |
| 支付配置 | 微信 V3、支付宝、敏感密钥 | `pay` 配置及掩码保存 | `******` 原样提交不会覆盖真实密钥 |
| 支付场景 | 小程序、公众号、H5、PC、iOS、Android 的渠道和默认项 | `payment_scene` 六终端 11 场景 | 每终端启用渠道中恰有一个默认项 |
| 用户充值 | 开关、金额限制、创建、详情、列表、预支付 | `recharge` 配置与归属订单 | 客户端只能为当前会员创建并消费本人订单 |
| 微信登录 | 小程序、公众号、开放平台 PC | `mnp`、`oa`、`open_pc` | 同一 UnionID 跨端归一到同一会员 |
| 首次补全 | 昵称头像、强制手机号 | 一次性 completion ticket | 完成必要步骤后才签发正式会员 token |
| 登录态绑定 | 小程序、公众号微信绑定 | `mnp`、`oa` 绑定 | 重复绑定幂等，跨会员冲突拒绝 |

## 业务规则与不变量

1. 充值订单的会员、最终金额、订单终端和支付状态以服务端数据为准；客户端只提交运行时终端、请求金额、订单 ID 和选定支付方式。
2. 小程序只支持微信支付；其余五终端支持微信和支付宝，共 11 个场景。启用充值时，每个终端至少一个启用渠道，且只能有一个启用的默认渠道。
3. 客户端只能调用预支付，不得调用或模拟渠道通知；只有验签成功的微信/支付宝回调可以结算。
4. 回调金额、币种、渠道、商户身份和应用身份必须与订单一致；第三方交易号唯一，重复成功回调幂等。
5. 微信登录只支持 `mnp`、`oa`、`open_pc`，不扩展 QQ、移动 App OAuth、解绑或账号合并。
6. 浏览器 OAuth state 高熵、哈希保存、绑定场景和站内返回路径、过期且一次性消费。
7. completion ticket 不是会员 token，只能补全资料或验证手机；消费成功后才签发正式 token。
8. OAuth identity 按微信客户端隔离，principal 按 UnionID 归一；身份或手机号已属于其他会员时拒绝，禁止静默合并。
9. 支付与 OAuth 凭据只由管理员管理；敏感字段回显掩码，提交掩码保留原值。

## 客户端消费边界

- 管理端表达支付配置、充值开关/金额和完整场景矩阵，以及用户、登录和微信开关。
- UniApp 根据运行时推导小程序/H5/iOS/Android 终端，消费 JSAPI、MWEB、NATIVE、APP、WAP、PAGE 返回结果。
- PC 固定终端为 PC，使用同源 `/api`，消费 NATIVE、MWEB、PAGE 等服务端返回场景。
- 没有真实凭据时，客户端必须展示渠道未配置或预支付错误，不得制造成功状态。

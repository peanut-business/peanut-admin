# Peanut Admin 功能需求矩阵

> 状态：Accepted and Recalibrated（2026-07-15），已通过 48 号复审，等待新编码批准
>
> 原则：P0 先证明安全内核和扩展契约可运行；P1 再形成市场可用后台；P2 承接生态和规模化运营。P1/P2 不得偷偷进入 P0。

## 1. 优先级定义

| 级别 | 含义 |
| --- | --- |
| P0 | 安全可运行内核和一条端到端扩展链路；可以继续开发，但不宣称已是完整公开产品 |
| P1 | 面向普通开发者可用、功能接近成熟后台的首个公开版本 |
| P2 | 插件生态、商业控制面或规模化运营阶段 |
| 不纳入 | 使用成熟外部工具，或属于具体业务系统，不进入通用底座 |

## 2. 可用后台基础

| 能力 | 优先级 | 说明 |
| --- | --- | --- |
| CLI 安装和环境检查 | P0 | 检查 PHP、扩展、数据库、目录权限，执行迁移并初始化管理员；可视化向导放 P1 |
| 登录、退出、会话续期 | P0 | 支持安全会话撤销和多端策略配置 |
| 邮箱密码凭证 | P0 | 第一条登录链路；使用框架/成熟密码哈希能力 |
| 手机号凭证 | P1 | 国内场景启用，与邮箱共同遵守全局凭证唯一规则 |
| 密码找回和重置 | P1 | 不自行设计加密算法，使用一次性、限时令牌 |
| 登录限流 | P0 | 防暴力破解；验证码和可替换挑战适配器放 P1 |
| 多凭证绑定 | P1 | 一个账号可绑定邮箱、手机号等多个凭证 |
| 全局凭证唯一和账号合并保护 | P0 | P0 保证邮箱唯一；手机号加入后使用同一冲突保护，账号合并放 P1 |
| MFA | P1 | TOTP 或 WebAuthn，复用成熟库 |
| SSO/OIDC | P1 | 企业客户需要时启用，不进入 P0 主链 |
| 个人资料和安全设置 | P1 | 头像、昵称、修改密码、已登录设备 |
| 国际化和主题 | P1 | P0 保证结构可扩展，不追求大量主题 |

## 3. 租户和成员

| 能力 | 优先级 | 说明 |
| --- | --- | --- |
| Tenant 增删改查和状态管理 | P0 | Tenant 是唯一 SaaS 客户隔离根 |
| 登录后租户选择/解析 | P0 | 登录后列出可用 Tenant；只有一个时自动进入 |
| 域名/路径租户解析 | P1 | 自定义入口先限定候选租户，仍需 Account/TenantMember 校验 |
| 租户切换 | P0 | 一个账号属于多个租户时显式切换 |
| TenantMember | P0 | 账号在租户内的成员身份，权限绑定在成员上 |
| 平台操作员和平台 RBAC | P0 | 管理租户和平台配置，但不自动获得租户业务权限 |
| 租户模块开通 TenantModule | P0 | 区分部署已安装、租户已开通和成员有权限 |
| 邀请成员 | P1 | 邮箱和手机号通道；邀请需要确认 |
| 管理员直接添加成员 | P0 | 二次确认后立即创建/绑定，不伪装成已接受邀请 |
| 成员停用和移除 | P0 | 撤销当前租户访问，不删除全局账号 |
| 租户套餐和额度 | P1 | 模块、人数、存储量、到期时间等 |
| 自定义域名 | P1 | 域名验证、证书和租户解析 |
| 集团/父子租户 | P2 | 等真实合同、授权和数据关系明确后实现 |
| 代运营授权 | P2 | 显式委托、时效、范围、复核和审计，不共享客户密码 |
| 平台支持会话 | P1 | 限时进入目标租户、显式授权、醒目标识和全程审计 |

## 4. 组织架构、权限和数据权限

| 能力 | 优先级 | 说明 |
| --- | --- | --- |
| 部门树 | P0 | 租户内部组织结构，不等于子租户 |
| 岗位 | P1 | 成员岗位和展示信息 |
| 角色 | P0 | 租户内角色；系统保留角色和自定义角色分开 |
| 菜单权限 | P0 | 控制可见导航，不能代替 API 授权 |
| 按钮/操作权限 | P0 | 控制页面动作和后端行为 |
| API 权限 | P0 | 后端独立校验，不能信任前端 |
| 成员与多角色 | P0 | 支持一个成员承担多个职责 |
| 基础数据范围 | P0 | 本人、本部门、部门及下级、全部、指定部门 |
| 业务对象范围 | P0 | 指定门店、仓库等；由模块提供可授权对象和查询规则 |
| 模块自定义 Data Provider | P0 | 同时提供列表谓词和单对象动作校验，覆盖读写、批量、导入导出和后台任务 |
| 数据权限合并规则 | P0 | 租户守卫永远取交集；单条授权内不同维度取交集；多个有效角色/授权取并集；P0 不提供显式 deny |
| 权限预览和有效权限查询 | P1 | 管理员能看到某成员最终拥有的功能和范围 |
| 权限变更审计 | P0 | 记录谁给谁改了什么权限 |
| 临时授权/审批授权 | P1 | 到期自动撤销，适合代班和敏感操作 |
| 关系自动继承权限 | 不纳入 | 集团、合作方、上下级关系不能自动产生访问权 |

## 5. 系统管理

| 能力 | 优先级 | 说明 |
| --- | --- | --- |
| 模块菜单和路由装配 | P0 | Module manifest 贡献菜单/路由；可视化菜单编辑放 P1 |
| 系统配置 | P1 | 区分平台配置、租户配置和模块配置 |
| 字典/参考数据 | P1 | 提供通用码表，不承载复杂业务主数据 |
| 文件和对象存储 | P1 | 本地/S3 兼容等适配器，优先 Flysystem |
| 素材库 | P1 | 文件分类、选择、引用和权限 |
| 通知基础设施 | P1 | 站内信、邮件、短信通道和模板 |
| 消息中心 | P1 | 已读状态、批量处理和跳转目标 |
| 操作日志 | P0 | 记录操作方租户/成员、目标租户/对象、动作、结果和关联 ID |
| 登录和安全日志 | P0 | 登录成功/失败、凭证变更、设备和 IP |
| 异常日志查看 | P1 | 展示已结构化的应用异常；不替代专业日志平台 |
| 定时任务管理 | P1 | 复用成熟调度能力，支持任务状态和执行记录 |
| 队列任务管理 | P1 | 复用成熟队列，提供失败重试和管理视图 |
| 导入/导出 | P1 | 通用 Excel/CSV 流程、权限和异步任务支持 |
| 备份/恢复接口 | P1 | 对接云数据库或成熟工具，并进行恢复验证 |
| 生产备份与恢复运行手册 | P0 | 即使没有后台按钮，也必须有自动备份方案和定期恢复演练 |
| Web SQL 编辑器/数据库管理 | 不纳入 | 使用 Adminer、DBeaver、云数据库控制台等成熟工具 |

## 6. 模块、插件和开发能力

| 能力 | 优先级 | 说明 |
| --- | --- | --- |
| 模块清单和启用状态 | P0 | 声明名称、版本、依赖、权限、菜单、迁移和配置 |
| 模块三层生效守卫 | P0 | 部署已安装、租户已开通、成员有权限缺一不可 |
| 模块间服务契约 | P0 | 只经公开服务/接口访问，不直接修改其他模块表 |
| 模块数据所有权 | P0 | 表、Model、Repository、迁移归属唯一模块；其他模块不得直接读写、JOIN 或执行其迁移 |
| 模块迁移和初始化数据 | P0 | 可重复、可回滚策略明确，并记录版本 |
| 模块测试模板 | P0 | 单元、集成、权限和租户隔离测试 |
| 产品方案 | P0 | 版本控制中的静态装配文件；不进入 P0 数据库，也不参与请求授权 |
| 插件安装/升级/卸载 | P1 | 插件是有生命周期的交付制品，不等同于模块 |
| 插件签名和兼容检查 | P1 | 防止安装不兼容或被篡改的制品 |
| 应用/插件市场 | P2 | 独立运营平台，不进入首个开源版本 |
| 代码生成器 | P1 | 生成标准 CRUD、权限、API、页面和测试骨架 |
| 可视化 API 参考手册 | P1 | 在 P0 OpenAPI schema 上增加完整搜索、示例和版本浏览 |
| 最小可构建开发文档站 | P0 | 在 Runtime 前先建立站点骨架，持续包含安装、核心概念、权限、Module 和升级说明 |
| 完整开发文档站 | P1 | 补齐搜索、版本切换、完整手册和自动生成 API 区域 |
| 编码规范和检查闸门 | P0 | PHP、TypeScript、文档、测试和提交范围检查 |
| 示例模块 | P0 | 只演示契约，不出现 DCS/Finance/门店经营业务 |

| 能力 | 优先级 | 说明 |
| --- | --- | --- |
| 统一 API 响应和错误码 | P0 | 错误可追踪，不把内部异常直接暴露给客户端 |
| API 版本和兼容策略 | P0 | 明确废弃周期和升级说明 |
| API Token/密钥 | P1 | 面向系统集成，独立于人员登录会话 |
| Webhook | P1 | 签名、重试、幂等和投递日志 |
| 幂等键和请求关联 ID | P0 | 支撑支付外的通用写入重试和链路排查 |
| 健康检查 | P0 | 检查 P0 实际配置的数据库、缓存和应用状态；P1 adapter 接入后再追加队列/存储检查 |
| 租户感知的缓存和最小异步上下文 | P0 | 实现缓存命名空间、Queue/CLI/Schedule 可信上下文 envelope 和测试 transport；任务管理、导出和文件仍属 P1 |
| 安全基线 | P0 | CSRF/CORS、密钥管理、依赖审计、敏感信息脱敏和安全响应头 |
| Docker 开发环境 | P0 | 便于开箱运行，不绑定唯一生产部署方式 |
| 发布包和数据库升级 | P0 | 版本化迁移、变更日志、升级前检查和回滚说明 |
| 自动远程升级所有客户实例 | P2 | 属于独立运营控制台，需安全通道和灰度机制 |
| 许可证和商业授权服务 | P2 | 开源核心与商业服务分离，后续单独设计 |
| 遥测和远程诊断 | P2 | 必须明确隐私、同意和可关闭策略 |

## 8. 业务功能边界

以下能力可以由 Peanut Admin 的业务模块或独立产品实现，但不属于底座 P0：

- 商品、类目、SKU、价格和促销。
- 库存、批次、库位、入库、出库和调拨。
- 门店、收银、订单、配送和售后。
- 仓储中心、采购、供应商和批发。
- 会计、账单、债务和 Finance Manager。
- DCS 的业务主体、交易关系和经营规则。
- 通用工作流/BPM、CRM、ERP、商城、支付和微信生态。

底座只提供这些模块需要的租户、成员、权限、数据权限、日志、文件、任务、配置和扩展契约。

## 9. 第一版可用性验收

P0 完成不以“目录和接口存在”为准，至少应验证：

1. 全新环境可安装并创建平台管理员和首个租户。
2. 用户可用邮箱密码登录；手机号凭证作为 P1 验收。
3. 一个账号加入两个租户后能正确切换，数据不串租户。
4. 一个租户能创建部门、成员、角色和菜单权限。
5. 数据权限能限制到本人、部门和虚构 WorkItem 指定对象。
6. 越权 API、伪造 `tenant_id`、跨租户 ID 均被后端拒绝并记录。
7. 示例模块能安装、迁移、启用、贡献菜单和权限，并验证 TenantModule 三层守卫。
8. 前后端核心包通过 Composer path repository 和 pnpm workspace 被脚手架消费；公共包仓发布作为 P1 验收。
9. 版本升级能执行迁移并给出失败恢复路径。
10. 文档中的安装和模块开发流程由干净环境自动验证。
11. 原生 SQL、缓存和最小 Queue Context adapter 通过跨租户攻击测试；P1 引入任务管理、导出和文件后必须复用同一测试契约。
12. 平台 Token/Session 不能直接调用租户业务 API，租户切换会生成新的受约束上下文。

## 10. P0 实施分段

P0 是安全架构可运行基线，不是一项一次性交给单个 Agent 的任务。建议分为：

1. P0-A：账号、凭证、Tenant、TenantMember、平台操作员和上下文安全链路。
2. P0-B：最小部门、角色、功能权限、数据权限、菜单和审计。
3. P0-C：Module/TenantModule 契约、示例模块、少量前后端核心包和最小 Admin Shell。
4. P0-D：CLI 安装、升级、备份运行手册、最小文档、工程闸门和全链路验收。

每段都要先完成模型和测试设计，再拆给低上下文 Agent；不得四段并行修改同一运行时仓库。

P0 通过后再生成 P1 计划，补齐手机号/多凭证、邀请、岗位、权限预览、配置、字典、文件、任务、导入导出、代码生成器和完整文档站，达到“可公开给普通开发者使用”的目标。

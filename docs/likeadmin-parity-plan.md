## 3. 并发与冲突控制

- 只读盘点可按参考后端、Peanut 后端、前端路由/API、数据库四个方向并行。
- 实施按业务域分配独立目录和独立文件集合；公共路由、权限、响应封装和数据库初始化由主线统一修改。
- 同一阶段先冻结契约，再分配代码任务，避免前后端围绕未确定字段反复修改。
- 子任务完成后只合入明确归属的文件；发现重叠时由主线统一处理，不进行相互覆盖。

## 4. 单项执行模板

1. 在 LikeAdmin 中执行目标业务，提炼能力、实体关系、规则、权限语义、状态流和用户可见结果。
2. 使用 CodeGraph 定位参考实现和 Peanut 对应实现，建立业务知识图谱与数据映射。
3. 按 Peanut Admin 既有 ThinkPHP 分层和开发规范实现，不增加双字段、双路由或参数兼容层。
4. 启动两套系统，对同一业务能力执行一次最低充分验收；不比较 UI、路由、接口形态和精确文案。
5. 记录有意不复制的参考缺陷，更新契约、本计划和 `likeadmin-parity-report.md`。

## 6. 复刻边界

- 一致性门槛是业务需求、能力、实体关系、规则、权限语义、状态流和用户可见结果。
- UI、页面路由、接口路径、参数名、响应 envelope 和精确文案可按 Peanut 既有规范实现。
- 不为形式一致建立兼容层，不复制 LikeAdmin 缺陷，不提前实现后续模块。

# LikeAdmin 系统设置与开发工具业务契约

> 范围：S01、T01。配置、充值支付、微信 OAuth、代码生成器、字典、调度、日志和维护的核心、页面消费与真实浏览器验收均已完成并封存。

## 1. 对齐原则

只对齐配置实际生效、支付/充值状态机、字典关系、调度语义、日志结果、维护能力和代码生成结果。页面框架、路由、接口名和响应外壳不要求一致；没有消费者的空壳配置、模板演示和参考缺陷不作为复刻目标。

## 2. S01 能力图谱

- 网站：后台/H5/PC 品牌资源、SEO、备案、服务/隐私协议和站点统计；保存后对应客户端立即消费。
- 用户：默认头像、登录方式组合、强绑手机、协议与第三方登录开关；开关必须对应真实登录行为，不能只有表单。
- 充值支付：充值开关和最低金额 → 用户创建归属订单 → 当前终端可用渠道 → 预支付 → 第三方回调 → 幂等入账/流水 → 管理端退款链。
- 支付场景：渠道凭据与终端场景分离；每个终端最多一个默认方式、至少一个启用方式，默认方式必须启用。
- 存储：local/qiniu/aliyun/qcloud；配置有效后才允许切换默认驱动，配置与默认引擎原子保存。
- 热门搜索：现有配置、词条事务替换和公开消费可复用，只补严格校验和权限。
- 客服：真实用户入口由 DE01 客服装修组件承载，不重复建设第二条无消费者的客服链。
- 交易四项设置两端都没有订单消费者，作为 Peanut 扩展保留，不列入本轮一致性门槛。

S01 的高风险门槛是充值支付真实闭环。订单归属、回调签名、第三方流水唯一、订单行锁、状态幂等和余额只增加一次必须由 Sol 实现；不得把真实支付状态机交给 Luna 设计。

### 2.1 充值支付冻结契约

- 充值配置 canonical 字段为 `status/min_amount/max_amount/scenes`；支持 PC、H5、公众号、小程序、iOS、Android 六终端共 11 条渠道场景。每终端至少一个启用渠道且最多一个默认渠道，默认渠道必须启用。
- 微信场景为小程序/公众号 JSAPI、H5 MWEB、PC Native、iOS/Android APP；支付宝场景为公众号/H5 WAP、PC Page、iOS/Android APP，小程序不得提供支付宝。
- 订单金额、会员和终端归属由服务端冻结；用户只能创建、查看、预支付自己的订单。微信 JSAPI 的 `openid` 从已验证 OAuth identity 内部取得，不信任客户端提交。
- 微信回调使用 V3 平台证书验签和 APIv3 AES-GCM 解密，支付宝回调使用 RSA2 验签；回调同时核验商户、应用、金额、币种、渠道、订单和流水。
- 订单与会员行锁、第三方流水唯一、重复回调幂等、冲突回调拒绝；余额、累计充值和账户流水仅增加一次。`pay_sn`、`transaction_id` 以可空唯一索引表达未支付状态。
- 支付传输边界可注入，生产实现使用 cURL；核心验收使用假传输，不等同真实商户联调。

### 2.2 微信 OAuth 冻结契约

- 只支持 LikeAdmin 实际具备的 `mnp`、`oa`、`open_pc`；不增加 QQ、iOS/Android OAuth、解绑或账号合并。
- `oauth_principal(provider,union_scope,union_id,member_id)` 表达 UnionID 归一主体；`oauth_identity(provider,client_key,subject,principal_id,member_id,terminal)` 表达客户端身份。相同 UnionID 可跨场景归一，不同客户端相同 openid 不得误合并。
- state 只保存 SHA-256 摘要、场景、站内返回地址、过期/消费时间；外部返回地址、错场景、过期和重放均拒绝。
- 首登资料/强绑手机号通过短期一次性 completion ticket 完成，不提前签发完整登录 token；占用手机号和身份冲突明确拒绝，不自动合并账户。
- begin/callback 双重检查开关和凭据；禁用会员拒绝登录。登录态绑定只支持 mnp/oa，且必须幂等、冲突拒绝。
- `app_secret` 采用 `******` 掩码回显与原样提交保留语义，并返回 `app_secret_configured` 供页面判断。

## 3. T01 能力图谱

- 字典：类型/数据 CRUD、筛选、状态与选择器；类型标识修改和数据冗余字段必须同事务同步；类型被数据占用时拒绝删除，无效 ID 不伪成功。
- 定时任务：CRUD、Cron 预览、启停、到期执行、耗时与错误；调度前必须原子认领/互斥，命令只允许注册表中的控制台命令。
- 操作日志：写请求记录、IP/时间筛选和导出；密码、Token、AppSecret、私钥、证书等所有层级递归脱敏。
- 环境/缓存：环境与目录检查、精确清缓存；只补权限并做一次最小验收。
- 代码生成器：读取数据表 → 导入元数据 → 字段/关系/树配置 → 同步 → 预览 → 隔离目录生成 ZIP → 所有者限时下载。路径、SQL 标识符、模板变量和下载令牌均需安全边界。
- 模板示例属于开发演示，不是 T01 强制业务能力。

## 4. Sol / Luna 边界

Sol 负责的唯一配置 Schema、原子写入、敏感值策略、支付与充值状态机、OAuth 身份与票据、调度锁与命令注册、日志递归脱敏、生成器元数据/路径/下载安全、迁移和权限节点均已冻结并落地。

在上述边界冻结并落地后，Luna 可负责纯配置页面、已有字典/任务/日志页面字段与权限按钮、支付配置管理页面、生成器列表/字段/预览/下载页面、前端类型检查和低 token 验收脚本。Luna 遇到新增字段、状态、命令、模板能力或路径语义时必须回流 Sol。

## 5. 最低充分验收

- S01 配置：读 → 非法保存不变 → 合法保存 → 对应客户端结果生效；普通角色查看/保存权限各一次。
- 充值支付：假传输边界创建单 → 可用渠道 → 预支付 → 幂等成功回调；核对归属、第三方流水唯一、余额和流水只增加一次。
- 存储不重复 M02 上传生命周期，只验证无效云配置不能切换默认引擎。
- 字典：类型改名事务同步；占用拒删；解除占用后删除。
- 定时任务：安全注册命令到期只执行一次；失败入错误态；重新启动清错；停止后不执行。
- 日志/维护：一条写日志完成筛选/导出并证明嵌套密钥脱敏；缓存 canary 被清除。
- 生成器：隔离夹具表导入 → 编辑 → 同步 → 预览 → ZIP；跨用户下载和路径越界均拒绝，最后精确清理。

## 6. 不复制的参考缺陷

不复制支付订单越权、重复回调重复入账、支付凭据进入操作日志、生成器未登录下载、动态 SQL 标识符拼接、共享生成目录竞态、任意命令执行、定时任务重复执行、字典级联误删和无效 ID 伪成功。

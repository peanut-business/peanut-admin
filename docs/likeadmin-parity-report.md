## 1. 结论

截至 2026-08-03，Peanut Admin 已完成 LikeAdmin 1.9.4 业务需求和产品能力复刻的最终验收。P01 知识图谱与实现定位、全部业务域以及 V01 全量菜单回归均已收口；Luna Playwright 独立会话 v01pm 按实际侧边栏逐个点击 30 个可见叶子菜单，30/30 成功。无 404/500、登录重定向或空白页，每页标题均为 `Peanut Admin` 且含主要业务内容；精简证据见 `output/playwright/v01/frontend-summary.json`。

业务差异已清零。装修/开发页仅有不影响呈现的 i18n fallback warning，不构成阻塞。V01 全程只读，未触发新增、保存、删除、启停或清缓存等写操作；DOC01/DOC02 也已完成，本 parity 工作没有待执行的下一项。

前端技术栈不同造成的布局、控件样式、字号、间距和交互动画差异属于可接受差异，不纳入阻塞项。以下内容必须对齐：

- 产品能力和用户能够完成的业务操作；
- 实体关系、关键数据、默认规则和校验语义；
- 权限边界、状态值、状态流转和各消费端结果；
- 分页、筛选、排序、导出及失败不写入等业务行为；
- 登录、会话、数据范围、事务边界和审计结果。

后端不机械复制参考项目的代码形式。实现必须落入 Peanut Admin 现有 ThinkPHP 8 分层、命名、响应封装、验证、异常和事务规范。UI、路由、接口路径、参数名、响应 envelope 和精确文案不要求一致；不建立兼容层，也不复制 LikeAdmin 缺陷。

## 4. 已确认差异

### 4.1 登录与会话

- 已修复 Peanut Admin 登录成功后直接采用无效 `redirect=login`、从而再次进入登录页的问题。
- 2026-07-28 真实浏览器验收：访问 `/login?redirect=login`，使用有效账号提交一次后进入 `/dashboard/workplace`。
- 已将无状态 JWT 改为服务端会话 token，并实现 8 小时有效期、最后 1 小时续期、终端、多端策略、session 级 IP 绑定、登录时间/IP 和按 IP 失败锁定；旧 JWT 发布后需重新登录。
- 2026-07-28 运行验收：认证迁移完成；`/api/user/info` 返回 code=20000、6 组菜单和 root `permissions=['*']`；真实浏览器使用新会话一次登录进入工作台。
- 2026-07-28 失败锁定验收：第 1～4 次保持可尝试，第 5 次进入锁定，第 6 次返回“密码连续5次输入错误，请30分钟后重试”；测试缓存随后清理。
- 2026-07-28 logout 双分支验收：合法终端只允许 `1/2`；`multipoint_login=1` 时登录、退出均返回 `20000` 且原 token 继续访问 info 返回 `20000`；`multipoint_login=0` 时退出后原 token 返回 `40100 / 登录超时，请重新登录`。测试期间临时配置已恢复。
- A02 的登录校验、服务端会话、IP 绑定、有效期/续期、失败锁定和退出语义均已完成最小充分验收，标记为已验收。
- 验收要求：一次有效提交进入有权限的默认首页；无效重定向不得覆盖默认首页；登录失败、禁用账号、失效令牌和退出登录的行为与参考系统语义一致。

## 5. 验收原则

每个任务必须同时满足以下条件后才能标记为已验收：

1. 建立参考业务的能力、实体关系、规则、权限语义、状态流和用户可见结果图谱；
2. 后端实现符合 Peanut Admin 既有 ThinkPHP 开发规范；
3. 前端覆盖参考系统的业务入口、核心信息和操作，不要求视觉、路由或接口形态一致；
4. 在两套真实运行系统中对同一业务能力执行一次核心路径；
5. 对业务结果、数据库不变量、权限和异常语义做一次最小充分验证；
6. 将结论和剩余差异回写本报告及实施计划。
